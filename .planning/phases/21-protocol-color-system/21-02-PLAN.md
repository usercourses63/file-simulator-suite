2. Add health state background tint rules AFTER the existing `.server-card--protocol-*` rules (added by plan 21-01). These provide a secondary visual signal beyond the left border (VIS-04). The health background overrides the protocol tint for unhealthy states:

```css
/* Enhanced health state indicators - background tint (VIS-04) */
/* Down: subtle red wash over entire card */
.server-card--down {
  background-color: rgba(239, 68, 68, 0.06);
}

/* Degraded: subtle yellow wash over entire card */
.server-card--degraded {
  background-color: rgba(234, 179, 8, 0.06);
}
```

Note: These override the protocol-tinted background for unhealthy/degraded cards. This is intentional — when a server is down, the urgency signal (red tint) should take priority over the protocol identity (protocol tint). Healthy cards keep their protocol tint. The CSS cascade handles this naturally since health classes appear after protocol classes in the className string.

However, CSS specificity is equal (both single class selectors), so ordering in the CSS file matters. Place these health background rules AFTER the `.server-card--protocol-*` rules in the CSS file to ensure they win.

3. Also add a subtle box-shadow for down state to make it even more prominent:

```css
/* Down state gets subtle red shadow for additional emphasis */

  box-shadow: 0 0 0 1px rgba(239, 68, 68, 0.15);
}
```
